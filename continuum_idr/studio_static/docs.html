CONTINUUM IDR SDK

Navigation continuity when GNSS is unavailable

Continuum is a local Python SDK that accepts ordered smartphone IMU samples and optional GNSS fixes, then returns position, speed, heading, uncertainty, and tracking health.

Start integratingView the evaluated replay
Prototype status

The repository contains a working research SDK, evaluation toolkit, replay Studio, portable JSON model runner, and Kotlin integration source. The current held-out evaluation does not meet the supplied under-10% drift target. Treat it as preliminary engineering evidence.

01Causal inputsThe runtime consumes ordered events and cannot access withheld reference data.
02Local executionThe Python engine and portable model do not require a live cloud service.
03Observable stateEvery output exposes mode, uncertainty, GNSS decision, and health flags.
GET STARTED

Run your first engine session

Install the package, load the supplied motion model, create the engine, and deliver measurements in timestamp order.

1Install the packageFrom the repository root:
python -m pip install -e .
2Create the engineThe model and engine must use the same IMU rate.
from continuum_idr import IDREngine, EngineConfig, MotionModelBundle

model = MotionModelBundle.load("models/motion_p0")
config = EngineConfig(imu_rate_hz=10.0, gnss_timeout_s=2.0)
engine = IDREngine(config, model)
3Send events and read stateGNSS initializes absolute position. IMU propagation continues between fixes.
from continuum_idr import GNSSFix, IMUSample

engine.on_gnss(GNSSFix(
    timestamp_s=100.0, latitude_deg=52.4001, longitude_deg=-1.5002,
    speed_mps=12.5, course_deg=92.0, horizontal_accuracy_m=3.5,
))

state = engine.on_imu(IMUSample(
    timestamp_s=100.1, accel_mps2=(0.12, 0.05, 9.81),
    gyro_radps=(0.001, -0.015, 0.002),
    gravity_mps2=(0.0, 0.0, 9.81),
))
print(state.tracking_mode, state.latitude_deg, state.longitude_deg)
CORE CONCEPTS

One state, optional measurements

Continuum keeps one estimator alive across the complete journey. IMU samples propagate motion. Accepted GNSS fixes correct the state. When fixes stop arriving, the same estimator enters dead reckoning and grows uncertainty.

→
Continuum coreMotion model + EKF
→
OutputState + confidence

PYTHON SDK

Installation

Continuum requires Python 3.10 or later. The repository package declares NumPy, pandas, scikit-learn, joblib, FastAPI, and Uvicorn.

python --version
python -m pip install -e .
python -m pytest tests/
Model files

The default integration expects a trained bundle under models/motion_p0/. Keep its manifest and model files together.

PYTHON SDK

Create an engine

IDREngine validates the model sampling rate when constructed. The engine begins uninitialized and establishes a local ENU coordinate frame from an accepted GNSS fix.

model = MotionModelBundle.load("models/motion_p0")
engine = IDREngine(EngineConfig(), model)

# Clear dynamic state while keeping configuration and model
engine.reset("new_trip")
PYTHON SDK

Send sensor events

Call on_imu() and on_gnss() in measurement-time order. Timestamps use seconds in the Python prototype. Accelerometer values use m/s² and gyroscope values use rad/s.

IMUSample

  • timestamp_s — monotonic measurement time
  • accel_mps2 — three sensor-axis values
  • gyro_radps — three sensor-axis values
  • gravity_mps2 — optional gravity estimate
  • sensor_id — profile identifier

GNSSFix

  • latitude_deg, longitude_deg — WGS84
  • speed_mps — optional ground speed
  • course_deg — clockwise from north
  • horizontal_accuracy_m — provider accuracy
  • fix_id — optional identity for diagnostics
PYTHON SDK

Read navigation state

Every event handler returns a NavigationState. You can also request the latest immutable snapshot with get_state().

state = engine.get_state()
payload = state.to_dict()

if state.latitude_deg is not None:
    update_marker(state.latitude_deg, state.longitude_deg)

show_quality(
    mode=state.tracking_mode.value,
    uncertainty_m=state.horizontal_uncertainty_m,
    flags=state.health_flags,
)

INTEGRATION GUIDE

Python application pattern

Your adapter owns the sensor connection and forwards normalized events to one engine instance. The client renders the returned state; it should never estimate a second position independently.

for event in source.events_in_timestamp_order():
    if event.kind == "gnss":
        state = engine.on_gnss(event.fix)
    else:
        state = engine.on_imu(event.sample)

    client.publish(state.to_dict())
Threading

Serialize calls into the engine. A live adapter may use a bounded queue, but it should preserve measurement ordering and report dropped samples.

INTEGRATION GUIDE

Android / Kotlin source integration

The android/ directory supplies Kotlin source for a portable tree runner and an Android location fallback engine. It is source integration rather than a published Maven package.

  1. Copy ContinuumLocationEngine.kt and PortableTreeRunner.kt into your application package.
  2. Copy models/portable/motion_portable.json into app/src/main/assets/.
  3. Add fine/coarse location and high sampling rate sensor permissions.
  4. Create the runner, start the engine, and handle its callback.
val modelJson = assets.open("motion_portable.json")
    .bufferedReader().use { it.readText() }
val runner = PortableTreeRunner.fromJsonString(modelJson)
val engine = ContinuumLocationEngine(this, runner)

engine.start(object : ContinuumLocationEngine.LocationUpdateCallback {
    override fun onLocationUpdate(
        location: Location, isFallback: Boolean,
        state: ContinuumLocationEngine.FallbackState
    ) { updateMap(location, state) }
})
Validation boundary

The included Kotlin code has not been established here as a released, device-certified Android SDK. Measure accuracy, latency, memory, and battery use on the target phone before making production claims.

API reference

IDREngine(config, model)

Creates an engine and validates rate compatibility.

on_imu(sample) → NavigationState

Validates and processes one IMU sample.

on_gnss(fix) → NavigationState

Validates, gates, and optionally fuses one GNSS measurement.

get_state(timestamp_s=None) → NavigationState

Returns the latest state snapshot.

reset(reason="manual")

Clears dynamic state and history for a new session.

set_road_graph(graph)

Attaches a road graph for optional candidate matching.

on_wheel_speed(sample) → NavigationState

Applies optional wheel odometry when configured.

REFERENCE

Health flags and rejected input

The prototype records degraded conditions in NavigationState.health_flags and exposes the latest GNSS decision. Clients should surface meaningful degraded status rather than hiding it.

INVALID_IMUOUT_OF_ORDER_IMUIMU_GAPSUSPECT_ALIGNMENTGNSS_REJECTEDLOW_CONFIDENCE
Input ordering

An out-of-order IMU sample is flagged and does not receive normal propagation. Large gaps increase uncertainty and are reported.

EVIDENCE

Known limitations

  • The IO-VNBD smartphone stream used here is approximately 10 Hz and cannot validate 200 Hz navigation accuracy.
  • The held-out evaluation currently reports zero outages below the supplied 10% drift target.
  • Absolute constant speed is weakly observable from a short IMU window, so entry state and motion priors matter.
  • The evaluation assumes a mounted passenger-car phone profile. Handheld use, motorcycles, Indian roads, and other phones need separate data.
  • The browser driver view replays desktop-generated evidence; it is not proof of on-device inference.
  • Road matching modules exist in the repository, but the displayed evaluation does not establish lane-level accuracy.
